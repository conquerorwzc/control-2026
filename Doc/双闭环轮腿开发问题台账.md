### 1.1 当前代码分层

```text
RobotTask（约 1 ms）
    └── ChassisTask
        ├── 左腿：读取两个关节反馈 → 链传动换算 → ACE FK → 真实末端 J 雅可比
        ├── 右腿：读取两个关节反馈 → 链传动换算 → ACE FK → 真实末端 J 雅可比
        ├── chassis_state：轮端、IMU、两腿状态 → 纯轮式 s 的十维状态；髋点量仅作诊断
        ├── 左右腿：VMC 广义力命令 → 主动轴 / 电机轴目标力矩
        └── chassis_output：维持既有 Stop / Enable 仲裁

纯运动学层
    └── kinematics/parallel_leg.[ch]
        输入：phi1、phi2、ACE 几何参数、虚拟末端支路
        输出：虚拟 D/E/C、真实 H/J、腿长、腿角、真实末端 J 雅可比；并提供纯几何 IK

传动层
    └── joint_transmission.[ch]
        输入：电机累计角
        输出：主动轴角 phi1 / phi2

VMC 映射层
    └── chassis_vmc.c
        输入：leg.vmc.force_command、leg.vmc.pitch_torque_command 与真实末端 J 雅可比
        输出：phi1 / phi2 主动轴力矩、前后电机轴等效力矩；仅在显式小力矩测试开关打开时由输出层发送
```

原则：纯运动学模块不包含 CAN、电机对象、FreeRTOS、PID 或硬件句柄；左右腿、电机方向、零位、链轮齿数等差异仅放在腿配置中。

状态读取层
    └── chassis_state.c
        输入：左右轮端反馈、IMU、左右腿 FK、虚拟腿雅可比和主动轴速度
        输出：十维状态；其中 s、s_dot 是左右轮端平均滚动的纯轮式纵向里程计状态

## 2. 当前 ACE 机构与标定数据

所有长度单位均为 **m**。下面仅记录当前 `parallel_leg` 模型使用的配置；早期直接求真实 P 点的几何数据已经失效，不能再与当前变量窗口的 D/E/C/H/J 混用。

| 参数 | 当前值 | 含义与状态 |
| --- | ---: | --- |
| l0 | 0 | 两主动轴中心距；当前 ACE 同心模型固定为 0。 |
| AH | 0.105 | 真实第一杆长度。 |
| HJ | 0.125 | 真实末端杆长度。 |
| CE | 0.0625 | 虚拟五连杆被动杆长度。 |
| k=CE/HJ | 0.5 | 程序计算，禁止独立手填。 |
| AD=AE=kAH | 0.0525 | 虚拟两根主动杆长度。 |
| CD=CE | 0.0625 | 虚拟末端两根被动杆长度。 |
| virtual_end_branch_sign | -1 | 当前实物支路满足 cross(E-D, C-D)<0；需随装配或角度定义改变重新标定。不要用画面“左/右”代替叉积判据。 |

FK 的计算顺序是：由 phi1、phi2 求 D、E；两圆交点求 C；再用 J=C/k 得到真实轮轴。真实腿长和腿角均只由 J 计算：

$$
l=\lVert J\rVert,
\qquad
\theta_l=\operatorname{atan2}(-J_x,J_y)
$$

真实末端雅可比由虚拟雅可比缩放得到：

$$
J_J=\frac{1}{k}J_C
$$

VMC 只使用真实末端 J 导出的 [l, theta_l] 雅可比，不能在 VMC 中再次除以 k。

当前手动运动时观测到的腿长范围是 0.0666987002 m 至 0.187587872 m。这只是已覆盖的观测范围，并非最终安全工作范围或 LQR 调度范围。

关节零位、链轮齿数、链传动方向和 CAN ID 以本车 `robot_config.h` 为唯一来源。每个电机的输出方向与反馈方向应配对配置为 `normal/normal` 或 `reverse/reverse`，但其物理正方向仍必须通过“主动轴 phi 增大”的真机试验确认。

## 3. 已关闭问题

### P-001：反馈读取函数反复发送 `DMMotorStop()`

| 项目 | 记录 |
| --- | --- |
| 状态 | 已关闭 |
| 现象 | 原 `WheelLeggedJointStopAndGetAngle()` 在约 1 ms 的循环内先 Stop 电机，再读取累计角。 |
| 影响 | 即使只是查看 FK，也会持续修改电机输出状态；未来接入控制器时会与 Enable、PID、力矩指令冲突。 |
| 根因 | 把“安全输出动作”和“读取反馈”放进了同一函数。 |
| 处理 | 改为 `WheelLeggedJointGetAngle()`，仅读取 `motor->measure.total_angle` 并更新 `feedback_ready`。 |
| 当前结论 | `DMMotorStop()` 只在每个关节执行 `DMMotorInit()` 后调用一次；运行期的 FK 更新不写 CAN 输出状态。 |
| 后续约束 | 任何读取、估计、FK、IK 函数都不得隐式 Stop、Enable 或发送控制量。 |

### P-002：临时 PID 测试与零力矩逻辑抢同一电机

### P-007：VMC 计算与小力矩测试不得绕过输出仲裁

| 项目 | 记录 |
| --- | --- |
| 日期 | 2026-07-30 |
| 状态 | 已关闭（计算链路与受限输出路径）；真机符号测试未完成 |
| 现象 | FK 已可观测，但尚没有统一的“虚拟腿广义力 → 两个主动轴力矩”数据通道，后续接平衡控制时容易让上层直接写电机。 |
| 影响 | 若 VMC 计算与电机输出混在一起，调试器手填变量或后续控制器可能在未完成保护前直接驱动关节，存在安全风险。 |
| 根因 | 虚拟腿坐标、雅可比、链传动和电机输出仲裁原本没有明确的分层边界。 |
| 处理 | 在每条 `WheelLeggedLegInstance_t` 内增加 `vmc` 对象；纯机构学层实时给出虚拟腿雅可比；`chassis_vmc.c` 计算广义力到主动轴/电机轴的映射；`chassis_output.c` 作为唯一出口，仅当本腿 `torque_test_enable=1` 且 VMC 有效时，才写入测试力矩。 |
| 验证 | 主机单测覆盖左、右腿的站立、前伸、后伸姿态：解析雅可比与中心差分一致，并验证小扰动关系和虚功恒等式；结果为 geometry 9/9、transmission 3/3 通过。H7 整机编译通过。 |
| 遗留风险 | 当前测试仅有单台电机轴 ±2 N·m 绝对限幅，尚未实现变化率限幅、机械限位保护和失控超时保护；必须悬空、低值、单腿测试。未经明确授权不得烧录。 |

首次悬空符号测试的变量窗口操作顺序如下。右拨杆必须先处于使能位置，使 `chassis_mode=CHASSIS_ON`；但此时两腿默认仍为零力矩。

```text
1. robot->chassis->left_leg.vmc.force_command = 0
   robot->chassis->left_leg.vmc.pitch_torque_command = 0
   robot->chassis->left_leg.vmc.torque_test_enable = 0

2. 确认 left_leg.vmc.valid = 1，且两个 *_motor_torque_output 均为 0。

3. 先只填一个很小的命令，例如 F = +1 N、Tp = 0；
   确认两个 *_motor_torque 的计算值和两个 *_motor_torque_output 均不超过 ±2 N·m。

4. 人手扶住悬空腿、远离机械限位后，最后才将
   left_leg.vmc.torque_test_enable = 1。

5. 观察伸/缩腿趋势后，先把 torque_test_enable 改回 0，
   再修改 F、Tp 或切换到另一条腿。
```

`front_motor_torque`、`rear_motor_torque` 是未限幅的数学映射结果；`front_motor_torque_output`、`rear_motor_torque_output` 才是实际送给达妙的参考，代码会强制限制在 ±2 N·m。不要同时打开两条腿，也不要在电机使能时暂停、断点或单步 MCU。

虚拟腿的坐标约定固定为：O 是髋点，P 是轮轴中心，x 向前/右为正，y 向下为正。

$$
l=\sqrt{x_P^2+y_P^2}
$$

$$
\theta_l=\operatorname{atan2}(-x_P,y_P)
$$

其中 θ_l=0 表示轮轴在髋点正下方；θ_l 增大表示轮轴向 x 正方向移动、虚拟腿顺时针摆。`F>0` 表示伸腿，`Tp>0` 表示 θ_l 增大。每条腿独立用：

$$
\boldsymbol\tau_\phi=\mathbf J_v^\mathsf{T}
\begin{bmatrix}F\\T_p\end{bmatrix}
$$

计算主动轴力矩；再按各主动轴自己的链传动 `direction × gain` 换算为电机轴目标力矩。左右腿不在 VMC 层额外翻转符号。

### P-008：历史上曾将十维状态 s 改为髋点里程计

| 项目 | 记录 |
| --- | --- |
| 日期 | 2026-08-01 |
| 状态 | 历史方案已关闭；当前已由 P-018 改回与 SJTU 原文一致的纯轮式 s |
| 现象 | 原 `s`、`s_dot` 仅由左右轮端转角和转速平均得到，腿前后摆动或伸缩时不能反映髋点 O 的真实纵向运动。 |
| 影响 | 十维模型中的位移、速度参考点与机身髋点不一致；后续以髋点为参考建模的 LQR 不能直接使用该状态。 |

| 验证 | 主机单测覆盖腿竖直退化为轮式结果、纯腿摆动、纯腿长变化和非法输入拒绝；H7 工程仅编译，不烧录。 |
| 当前结论 | 髋点里程计继续作为诊断量，但不进入十维状态或当前 K。当前 LQR 使用 P-018 定义的纯轮式 `s/s_dot`；两种参考点不能混用，任何切换都必须重新建模和生成 K。 |

### P-010：虚拟末端支路符号不直观，容易选到镜像轮轴

## 4. 当前风险与待解决问题

### R-001：已有四输入闭环仲裁与故障锁定，但机械和接触保护仍不完整

当前六台电机的 Stop、Enable 和力矩参考只经过 `chassis_output.c`；右拨杆中档是唯一人工闭环请求，状态、轮反馈、LQR、腿长控制、VMC、配置或数值失效后会 Stop 并锁定，必须退出中档后重新进入。仍缺少机身俯仰角/角速度硬阈值、轮速阈值、关节机械限位、打滑/离地检测、电机温度电流保护和关节力矩变化率限制；这些未补齐前只能做保护架低幅验收。

### R-002：轮毂、IMU、遥控器已进入四输入闭环，但真机物理合同尚未全部验收

轮毂反馈已用于纯轮式 s/s_dot，IMU 已用于 Yaw 与机身 Pitch，左右腿 FK/Jacobian 已用于腿角和 VMC；LQR 的 Tp_R/Tp_L 进入左右 VMC，Tw_R/Tw_L 进入左右 H6215，遥控器右拨杆中档请求闭环。尚未完成 H6215 正命令方向、单轮 Yaw 响应、完整四输入保护架平衡、打滑/离地与饱和后的稳定性验收，因此“软件链已接通”仍不等于“整车已稳定”。

### R-003：达妙反馈有效标志的判定仍需确认

当前 `feedback_ready` 使用 `measure.state != 0u` 进行粗略判断。后续应确认达妙协议中各状态值的含义，明确哪些状态代表正常反馈、失能、故障或离线。

### R-004：VMC 已有受限真机输出，但完整安全保护仍未完成

目前板端实时计算：主动轴角 → 真实末端 J 的腿长/腿角与雅可比，VMC 命令 → 主动轴/电机轴等效力矩。当前人工使能只保留遥控器右拨杆中档；输出还必须通过状态、LQR、腿长控制、VMC、反馈和故障锁定检查。单台 J4310 输出被限制为 ±2 N·m，轮毂 Tw 另有限幅和变化率限制。后续还需要：

1. 为达妙确认纯力矩模式、力矩单位和可持续允许范围。
2. 在唯一 `chassis_output` 出口补充变化率限幅、机械限位保护、失控超时和故障锁定状态机。
3. 对雅可比接近奇异、FK 无效、反馈失效和腿长超工作范围实现强制降额/清零。
4. 悬空、小力矩、物理限位充分避让的条件下，逐项确认左右腿 F、Tp 的力矩符号。
5. 以已接入的 IMU、轮速和腿部状态建立纵向状态估计后，再接入 LQR / 平衡控制。

### R-005：工程仍存在一个既有编译告警

当前已知告警为 `IMU_LeverArm_Compensation declared static but never defined`。它与本轮腿部 FK/IK 修改无直接关系，但后续应单独定位并消除，避免真正的遗漏被告警淹没。
