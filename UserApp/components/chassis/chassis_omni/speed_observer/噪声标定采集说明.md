# 速度观测器噪声标定采集

应用层采集适配器调用已有 `VOFAInit()` / `VOFAJustFloatSend()`，未修改 Modules、BSP 和硬件串口初始化。已根据四份 CSV 应用首轮 Q/R，优先纯平动 vx/vy、纯转动 wz，并保留真实机械运动加速度；依据见 [整定说明](noise_calibration/2026-10-12-tuned/整定说明.md)。

## 串口与数据格式

噪声采集和 PID 调参采集统一使用原裁判系统的 **USART6**。采集期间应用不初始化裁判串口协议，避免重复注册；USART1 导航和 CAN 遥控保持工作。两种采集互斥，不能在一个串口混发。

开关位于 `UserApp/robot/sentry_omni_chassis/robot_config.h`：

| `CHASSIS_VOFA_MODE` | 行为 | MCU TX 引脚 |
| --- | --- | --- |
| 0 | 关闭 VOFA，保留导航和裁判系统原通信 | — |
| 1 | USART6 输出本文件定义的噪声采集数据，暂停裁判系统接收 | PG14 |
| 2 | USART6 输出 PID 调参数据，暂停裁判系统接收 | PG14 |

当前默认值为 **1**，用于 IMU 静止残余零偏及噪声采集。切回 PID 调参时改为 **2**，采集完成后改为 **0** 恢复裁判通信。采集期间上报的裁判相关字段保持零值。修改模式后需要重新编译、烧录。旧 `CHASSIS_NOISE_VOFA_PORT` 开关已移除；PID 页定义见 [PID调参采集说明](PID调参采集说明.md)。

`CHASSIS_VOFA_MOTOR_ID` 选择唯一回传的电机，默认 ID1；允许 1～4，对应左前、左后、右后、右前。四轮仍全部参与运动学和速度观测器，只减少原始电机数据的回传路数。

- 协议：**JustFloat**，小端 float32，25 通道，每帧 104 字节，帧尾 `00 00 80 7f`。
- 串口：**115200，8 数据位，无校验，1 停止位，无流控**。
- 输出频率：**50 Hz**，每 20 ms 最多一帧；约 5200 字节/s，占串口带宽约 45.1%。
- 在 `ChassisTask()` 之后发送，不降低底盘任务和 EKF 的原有运行频率。
- UART TX 忙时跳过本帧，下一帧不补发，避免改写仍在 DMA 发送的 VOFA 静态缓冲。
- 序号按 20 ms 时隙递增。跳号可能来自任务延迟、串口忙或 PC 端丢帧；配合采样时间判断，不能仅凭跳号认定是线路丢包。

接线使用 **3.3 V TTL USB 转串口**：板 TX → 转换器 RX，GND → GND。采集不需要 PC 发送数据；转换器 TX 可以不接。不要把 TTL 接口接成 RS232 电平。

## 25 个通道

VOFA 按下列顺序显示。若软件从 1 编号，则“通道 0”对应显示的第 1 路。

| 通道 | CSV 建议列名 | 含义 | 单位 |
| --- | --- | --- | --- |
| 0 | seq | 20 ms 采集时隙序号，模 2^24 | 无 |
| 1 | time_s | 本轮底盘采样时刻，系统启动后时间 | s |
| 2 | observer_dt_s | 本轮观测器实际步长 | s |
| 3 | gyro_x | 底盘系角速度 x | rad/s |
| 4 | gyro_y | 底盘系角速度 y | rad/s |
| 5 | gyro_z | 底盘系角速度 z，速度 EKF 的陀螺仪观测量 | rad/s |
| 6 | imu_ax | IMU 点去重力、低通后的 x 加速度 | m/s² |
| 7 | imu_ay | IMU 点去重力、低通后的 y 加速度 | m/s² |
| 8 | imu_az | IMU 点去重力、低通后的 z 加速度 | m/s² |
| 9 | center_ax | 杆臂补偿后实际送给速度 EKF 的 x 加速度 | m/s² |
| 10 | center_ay | 杆臂补偿后实际送给速度 EKF 的 y 加速度 | m/s² |
| 11 | wheel_vx | 四轮测速正解 vx | m/s |
| 12 | wheel_vy | 四轮测速正解 vy | m/s |
| 13 | wheel_wz | 四轮测速正解 wz | rad/s |
| 14 | ekf_vx | 速度 EKF 输出 vx | m/s |
| 15 | ekf_vy | 速度 EKF 输出 vy | m/s |
| 16 | ekf_wz | 速度 EKF 输出 wz | rad/s |
| 17 | motor_dps | 所选电机测速 | 电机轴 °/s |
| 18 | motor_current_raw | 所选电机反馈电流 | 协议码值 |
| 19 | motor_temp_c | 所选电机温度 | °C |
| 20 | motor_id | 所选电机 ID | 1～4 |
| 21 | imu_temp_c | BMI088 温度 | °C |
| 22 | status | 状态位图，以整数数值装入 float | 无 |
| 23 | imu_count | INS 更新计数低 24 位 | 无 |
| 24 | wheel_residual | 四轮运动学一致性残差 | m/s |

全部向量已经按安装配置转换到底盘系：**+x 朝电池、+y 向左、+z 向上，+wz 俯视逆时针**。gyro 已经过现有驱动的启动零偏扣除，不能再当成未标定的原始芯片输出。电机测速已经过极性校正和驱动现有的低通。

IMU 位置目前采用 `(rx, ry)=(0, -0.1335) m`。`imu_a*` 是 IMU 安装点加速度，`center_a*` 才是中心加速度；静止时二者的差异也有助于检查角速度差分带来的噪声。`center_a*` 在短时无新样本时可能保持旧值，必须结合状态判断。

2026-10-12 改进后，通道 9/10 改为匹配低通后的杆臂补偿输出：角加速度和 wz² 补偿项使用 INS.AccelLPF 的相同时间常数（当前 8.5 ms）。25 路通道顺序、频率和串口保持原有定义。建议新日志命名为 `静止_匹配低通.csv`、`转动_匹配低通.csv`，静止保留同样机构运行状态，转动保留正反向和起停过程，用于比较静止方差及动态补偿效果。旧日志不能用于宣称本版已经达到某个实测降噪倍数。

改进后的 `new.csv` 转动及短暂停转验证见 [转动验证报告](noise_calibration/2026-10-12-new-rotation/验证报告.md)：起始短停转的中心 ax 标准差约 0.189 m/s²，噪声放大明显改善；持续转动后的周期残差和停转恢复仍需进一步检查，未据此写入新的 Q/R。

四轮残差为 `(m_LF-m_RF-m_LB+m_RB)/(4K)`，`K` 是电机轴速度与轮缘线速度的换算系数。理想刚体无滑动时应接近零；非零可能来自轮速不同步、几何误差、接触不一致或打滑。残差为零也不能证明速度准确，例如四轮共同的比例误差不会被它发现。

## 状态位

`status` 转为整数后按位读取，置 1 的含义如下：

| bit | 含义 |
| --- | --- |
| 0 | 本轮存在已初始化 INS 的传感器快照 |
| 1 | 本轮四轮输入同时满足新样本、在线和新鲜度要求 |
| 2 | 本轮给 EKF 提供了新的 gyro_z 样本 |
| 3 | 本轮中心加速度输入有效，可能是允许时间内保持的样本 |
| 4 | 本轮速度观测器成功更新或重置；不等于所有传感器有效 |
| 5 | 观测器已有速度初值 |
| 6 | 本轮 dt 超过 max_dt，进入重置/等待分支 |
| 7 | 底盘控制模式为 CHASSIS_POWER_OFF |
| 8 | ID1/LF 电机在线 |
| 9 | ID4/RF 电机在线 |
| 10 | ID2/LB 电机在线 |
| 11 | ID3/RB 电机在线 |
| 12 | 本轮融合速度可供速度外环使用：估计成功、轮速校正未超时且四轮在线 |
| 13 | 三轴速度 PID 已启用并预置历史，当前处于闭环状态 |
| 14 | 本轮实际计算了 yaw_hold_pid；仅用于采集，不自动启用航向保持 |

bit 1～3 表示送入滤波器前的输入资格；数值异常仍可能被滤波器拒绝。bit 0 和 INS 计数仅表明软件采集/计算正在运行，不替代 IMU 硬件故障检测。

传感器值在底盘原有短临界区内复制；轮速正解、EKF 输出与快照来自同一轮 `EstimateSpeed()`。四个电机反馈由各自 CAN 帧更新，因此这仍不是四轮硬件同步采样。

## 录制步骤

启动阶段先保持车体静止，等待现有 IMU 温控和启动零偏标定完成；能看到数据后再等约 30～60 s，检查通道 21 温度是否稳定在现有控制目标约 40°C。

按顺序单独录制，保留完整 25 路原始数据，优先导出 CSV，**不要只发曲线截图或只导出融合速度**：

1. **`01_static_off.csv`，60 s**：轮子落地，底盘关闭输出，整车静止，不触碰。用于计算 gyro_z 的残余均值、随机方差，以及去重力和中心加速度的方差。
2. **`02_static_enabled.csv`，60 s**：轮子落地，遥控器手动底盘坐标模式、平移和拨轮均回中，目标速度为零并确认整车静止。保留实际云台等设备的运行状态，说明是否开启，用于比较工作振动对噪声的影响。
3. **`03_vx.csv`、`04_vy.csv`，各约 30～60 s**：分别缓慢加速、匀速数秒、减速静止，再反方向重复。使用平整地面和较低速度，避免把明显打滑当作普通随机噪声。
4. **`05_wz.csv`，约 30～60 s**：原地低速逆时针、停转、顺时针；各含缓慢起转、匀速和停转。用于核对 wheel_wz 与 gyro_z、一致性残差和杆臂补偿。

右拨杆中位/上位对应当前底盘坐标的 CHASSIS_ROTATE，左拨杆中位选择手动；拨轮回中表示不主动自旋。左摇杆向前为 +vx，向左为 +vy，拨轮负方向为 +wz。静止使能组必须实际确认不转、不移，再开始计时。

第一轮先发前两个静止文件即可；动态文件随后补充。发送时注明地面、是否落地、设备开启情况、是否有肉眼可见晃动。保留导出文件自己的时间列，同时保留通道 0、1、2、22、23。

当前已配置启用三轴速度外环。使能静止组会包含速度外环对测速噪声的响应；若要对比外环关闭时的基线，可将 `chassis_init_config.enable_speed_hold` 设为 0 后另录一组，并在文件名中注明。底盘关闭输出时三个速度 PID 自动清空，不参与控制。

## 数据能标定什么

- 对稳定静止段，分别计算均值、去均值样本方差 `sum((x-mean)^2)/(N-1)`、异常值和自相关。gyro_z 方差用于 `gyro_variance` 的参考；残余均值应单独检查零偏，不能简单靠增大 R 掩盖。
- `center_ax/center_ay` 对应速度 EKF 的实际加速度输入，可据此给出 `accel_variance` 参考；`imu_a*` 用于分清姿态/重力去除和杆臂补偿噪声。
- 静止轮速可能因测速量化全部为零，**不能据此把 wheel_variance 设为零**。实际运动时的轮速误差需要动态对比、重复测量，必要时增加外部距离/角度参考。
- `wheel_wz-gyro_z` 包含两种传感器误差、不同滤波延迟、不同步与模型误差，不能直接把该差值的方差当作轮速方差。
- 过程噪声 Q 还包含未建模运动、滑移等影响，不能仅靠静止记录唯一确定。动态日志用于检查延迟、残差和参数合理性；没有独立速度真值时，只能给出带假设的整定建议。
- 这里输出是原有高频数据的 **50 Hz 抽取快照**，没有额外做均值或低通。可估计稳定段的幅度统计，但不能用于识别完整的高频噪声谱；现有低通、重复使用加速度和样本自相关，也意味着不能机械地假设每个高频 EKF 输入都统计独立。
- 配置填写的是**方差**，不是标准差；现有过程噪声按 `Q=q*dt` 使用，加速度方差通过 `dt²` 加入预测协方差。

## 实现位置

- `chassis.h`：`ChassisObserverTelemetry_s`，采集快照。
- `chassis.c`：在原有采样临界区内复制传感器数据，并保存本轮输入状态。
- `speed_observer/observer_vofa.c`：固定通道映射、50 Hz 节流、DMA 忙保护。
- `UserApp/robot/sentry_omni_chassis/robot.c`：串口协议切换、初始化和周期调用。

已收到静止（包含其他机构工作振动）、落地带载平动和原地转动三份日志。统计结果、输入噪声放大问题及候选参数见 [2026-10-12 标定报告](noise_calibration/2026-10-12/标定报告.md)。已得到工作噪声基线，轮速 R 和过程 Q 尚不能唯一确定；该轮分析未写入固件参数。

采集路由及通道已更新为 USART6 和单个代表电机。验证范围与限制见 [PID调参采集说明](PID调参采集说明.md)；旧版四电机日志的 17～20 通道与当前版本含义不同，不能混用。
