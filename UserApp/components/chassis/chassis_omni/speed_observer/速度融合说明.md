# 底盘速度融合观测器

本目录的 `speed_observer.c/.h` 已从轮腿的一维位置/速度/加速度模板改为当前全向轮底盘的三状态速度 EKF。修改只针对 `chassis_omni`，其他轮腿观测器不变。

## 当前运行状态

观测器已经在 `ChassisTask() -> EstimateSpeed()` 内接入，CMake 已加入该目录的源文件。融合速度现用于三轴速度外环反馈，详见 [速度闭环说明](../速度闭环说明.md)；尚未增加导航协议的融合速度上报字段。

当前已确认 C 板水平安装，IMU 原始 +X 朝后、+Y 朝右、+Z 朝上；IMU 位于底盘中心 -y（右侧）约 133.5 mm，配置偏移为 `{0.0f, -0.1335f}` m。安装校正配置为 `Yaw=180°、Pitch=0°、Roll=0°`，对应 X/Y 同时取反、Z 保持不变。用户反馈已完成全部验证，现已配置开启陀螺仪观测与加速度预测：

```c
.enable_imu_sampling = 1,
.observer_imu_calibrated = 1,
.observer_accel_enabled = 1,
```

采集开关会调用现有 `INS_Init()` 并启动 INS 任务，独立于两个融合开关。使用当前在线零偏配置，启动期间保持底盘静止，等待温度稳定及标定完成。

轴向核对可观察 `robot->chassis->chassis_IMU->Accel[]` 与 `Gyro[]`，分别为 m/s² 和 rad/s。当前安装校正为 Yaw=180°、scale 为 1、CenterOffset 为零，INS 输出已经转换为底盘系；`BMI088.Accel/Gyro` 仍是安装旋转前的传感器轴向。Accel 保留重力：水平静止时 Accel[2] 应约 +9.81；抬高车头后静止时 INS Accel[0] 应增加，抬高左侧后 INS Accel[1] 应增加；俯视逆时针旋转时 INS Gyro[2] 应为正。不要用已去重力的 MotionAccel_b 判断静止 Z 朝向。

首组新鲜四轮反馈到齐后初始化状态；有效陀螺仪样本到达后融合 wz，获得相邻有效 IMU 样本后加入加速度预测。输出保存在 `speed_observer.fused`。两个融合开关都置 0 时仍可退回轮速卡尔曼滤波模式。

## 状态与观测

状态 `x=[vx,vy,wz]`：底盘几何中心、机体右手系；电池方向为 +x，左为 +y，俯视逆时针为 +wz；单位分别为 m/s、m/s、rad/s。

输入分为三类：

| 输入 | 来源 | 作用 |
|---|---|---|
| 轮速 vx、vy、wz | 四个 `speed_aps` 经 `OmniForward()` 正解 | 观测校正，H=I |
| gyro_z | 安装方向校正后的 `INS.Gyro[2]` | 独立角速度观测，H=[0,0,1] |
| accel_x、accel_y | `INS.MotionAccel_b` 去重力加速度，经杆臂补偿 | 状态预测输入，不是速度观测 |

不使用 `MotionAccel_n`，因为状态是在底盘机体系表达。`INS.Gyro` 使用现有驱动启动零偏标定后的数据；本三状态观测器没有增加零偏状态，不能自动消除后续温漂。轮速观测的三个分量暂按独立噪声处理，实际相关性需要后续日志评估。

## EKF 预测模型

加速度有效时，机体系速度的时间导数为：

```text
dvx/dt = ax + wz*vy
dvy/dt = ay - wz*vx
dwz/dt = 角加速度过程噪声
```

旋转项来自机体系自身转动，不能漏掉。例如惯性系中沿直线匀速运动、同时车体逆时针旋转时，机体系中的速度向量会顺时针转动，即使惯性加速度为零也不能保持 vx、vy 不变。

采用一阶离散预测，实际 dt 来自 DWT：

```text
vx' = vx + (ax + wz*vy)*dt
vy' = vy + (ay - wz*vx)*dt
wz' = wz

F = [  1      wz*dt     vy*dt ]
    [ -wz*dt  1        -vx*dt ]
    [  0      0         1    ]

P' = F*P*F^T + Q
Q  = diag(process_noise)*dt
```

加速度采样噪声另向 P 的 vx、vy 对角项增加 `accel_variance*dt²`。当加速度未标定或过期时，切换为机体系速度随机游走预测（F=I），不会把“没有加速度数据”伪装成“测到了零加速度”。

四轮速度观测和陀螺仪观测以标量顺序更新。每次采用 Joseph 形式更新协方差：

```text
S = H*P'*H^T + R
K = P'*H^T / S
x = x' + K*(z-H*x')
P = (I-KH)*P'*(I-KH)^T + K*R*K^T
```

固定三状态小矩阵直接保存在实例中，不动态分配内存；因此没有沿用通用 `KalmanFilter_t` 的动态内存管理。保留了模板的配置、Init/Update/Reset 实例化接口思想，但输入、状态和预测模型已按全向轮底盘重写。

## IMU 安装偏移补偿

`observer_imu_offset={rx,ry}` 表示**底盘中心指向 IMU** 的向量，单位 m，x 前正、y 左正。平面运动下：

当前近似安装值：`rx=0 m`、`ry=-0.1335 m`；后续可用旋转日志进一步检查补偿精度。

```text
a_imu = a_center + alpha × r + omega × (omega × r)

ax_center = ax_imu + angular_accel*ry + wz²*rx
ay_center = ay_imu - angular_accel*rx + wz²*ry
```

统一更新函数内部调用私有 `LeverArmUpdate()`，对角加速度与向心项做匹配低通后补偿，再送入 EKF。滤波历史收在 `speed_observer` 中，不改 Modules 的 INS 计算。

现有 `MotionAccel_b` 已经去重力并低通。如果直接减去未滤波的角加速度/向心项，两边带宽和延迟不同，会把陀螺仪抖动带入中心加速度。因此读取同一份 INS 快照中的 `AccelLPF`（当前 0.0085 s），对补偿项使用相同的一阶低通：

```text
dt_imu = 相邻两次被底盘消费的新 IMU 样本之间的实际时间
tau    = INS.AccelLPF
k      = dt_imu / (tau + dt_imu)

alpha_filtered = (tau*alpha_filtered_previous + wz_now-wz_previous) / (tau+dt_imu)
wz2_filtered   = wz2_filtered_previous + k*(wz_now²-wz2_filtered_previous)

ax_center = MotionAccel_b[0] + alpha_filtered*ry + wz2_filtered*rx
ay_center = MotionAccel_b[1] - alpha_filtered*rx + wz2_filtered*ry
```

角加速度公式等价于对差分结果做低通，并避免先生成可能很大的 `delta_wz/dt` 中间值。向心项采用 **低通(wz²)**，不是 **低通(wz)再平方**。这使两种杆臂补偿项的带宽尽量与现有加速度匹配，而不是给已经低通的 MotionAccel_b 再增加一层延迟。用于速度 EKF 的 gyro_z 观测保持原来的样本，不使用这里的低通替代。

滤波器只随新的 IMU 样本更新，重复样本不再差分/低通；两次消费之间的间隔会累加。首次样本只建立角速度基准，角加速度置零、向心状态从当前 wz² 初始化，该轮暂不提供加速度预测。超出 20 ms 新鲜度、INS 未初始化或计数回退、异常时间、无效输入时清除历史，恢复后重新建立基准，避免跨中断差分。EKF 调试长暂停的复位逻辑仍然生效。

底盘可能跳过 INS 的中间样本，因此这是对高频 INS 低通的近似带宽匹配，不能保证任意丢采样时逐点完全一致。启动和恢复后也可能存在短暂滤波过渡，需要实际转动起停验证。

`imu_init_config.CenterOffset` 必须保持零，避免和已有 INS 杆臂处理重复。这里只处理平面刚体运动，不处理明显俯仰、横滚的完整三维杆臂效应。匹配低通降低差分噪声放大，但不能代替安装、姿态和噪声标定。

## 采样、有效性与输出

接入层在短 FreeRTOS 临界区内复制四轮反馈和 INS 数据，计算在临界区外进行。

- 四轮分别用现有 `feed_cnt` 判断新反馈；四轮都出现未消费样本且在线、新鲜时，才把这一组轮速作为观测校正。原始四轮正解仍单独保留。
- IMU 复用现有 `QEKF_INS.UpdateCount`，没有修改 Modules 层。当前 INS 任务优先级高于机器人任务，在当前同步计算流程下，底盘取到的是已完成的一轮数据；以后若调整任务优先级或在 INS 更新途中增加阻塞，必须复核这一前提。
- 陀螺仪同一轮样本只校正一次。加速度作为预测输入可短时保持，默认超过 20 ms 不再使用。
- 这个计数证明姿态计算发生了更新，不等于新增了 BMI088 硬件故障检测；仍依赖既有驱动正常读取。
- dt 必须为正且不超过 50 ms。调试暂停等长间隔后，只在有新鲜轮速时重置估计，否则等待重新播种。
- NaN/Inf 输入会被拒绝，有限性检查使用位模式，避免 Release 的 `-Ofast` 消除常规有限值检查。

上述处理只控制观测器是否使用数据，不改变现有电机急停与控制策略。无观测时仍可能只进行预测，输出不能据此认定为有效实测速。

调试观察项：

```c
robot->chassis->speed_observer.wheel;          // 未融合的轮速正解
robot->chassis->speed_observer.fused;         // 最新成功的观测器输出
robot->chassis->speed_observer.updated;           // 本周期是否成功更新/重置
robot->chassis->speed_observer.seeded;       // 是否已有初始化速度
robot->chassis->speed_observer.used_gyro;    // 上次成功更新是否用了陀螺仪观测
robot->chassis->speed_observer.used_accel;   // 上次成功更新是否用了加速度预测
robot->chassis->speed_observer.covariance;   // 3×3 协方差
```

更新失败时 speed_observer.fused 保持上次成功值。`speed_observer.updated` 也可能表示纯预测成功，不是传感器健康标志；`used_gyro/used_accel` 须配合当前更新状态理解。

## 配置和启用顺序

参数位于 `UserApp/robot/sentry_omni_chassis/robot_config.h`。已按用户“纯平动 vx/vy、纯转动 wz 优先”的要求，应用四份 CSV 支持的首轮 Q/R，见 [整定说明](noise_calibration/2026-10-12-tuned/整定说明.md)。机械/云台偏心引起的真实运动加速度保持参与预测。旧 [标定报告](noise_calibration/2026-10-12/标定报告.md) 中的中心加速度方差来自改进前的直接差分，不能直接视为本版测量结果。

1. 保持两个开关为 0，核对轮速正解与滤波输出的三轴方向、单位。
2. 测定 IMU 安装方向，配置现有 `imu_init_config.Yaw/Pitch/Roll`，保持 `scale={1,1,1}`。确认经过 INS 安装校正后，前进加速度在 x 轴、左移加速度在 y 轴，逆时针角速度在 +z 轴。不能直接把机械角度套入现有旋转实现而不验证。
3. 核对零偏，置 `observer_imu_calibrated=1`。此时初始化 INS 并加入 gyro_z 观测，加速度开关仍为 0。现有在线启动零偏标定需要静止。
4. 测量中心到 IMU 的 rx、ry；核对静止 `MotionAccel_b` 接近零以及旋转杆臂补偿，才置 `observer_accel_enabled=1`。
5. 用运动日志调节噪声。增大某传感器的 R 会降低其权重；增大过程噪声通常会提高对新观测的跟随程度。这里填写的是方差，不是标准差。

不要只把两个开关置 1；应先验证当前安装转换、残余零偏和近似偏移参数。

宿主测试直接编译正式观测器源码，覆盖噪声速度融合、陀螺仪权重、长期协方差正定性、旋转坐标系、加速度积分、切向/向心杆臂补偿、缺失观测、异常时间和 NaN/Inf，包含 `-Ofast` 构建验证。

```sh
gcc -std=c11 -Wall -Wextra -Ofast Utils/tests/test_omni_speed_observer.c UserApp/components/chassis/chassis_omni/speed_observer/speed_observer.c -lm -o observer_test
./observer_test
```

本次新增测试覆盖：带时间抖动的正反转杆臂补偿、差分噪声抑制、真实角速度变化的积分保留、启动时已转动、重复样本、超时恢复、计数回退、NaN/Inf 及调试暂停。模拟白噪声输入下角加速度 RMS 约为原始差分的 0.0766（约降低 13 倍），这是合成信号测试，不能作为实车降噪倍数。正式 chassis、observer、PID 及 VOFA 宿主测试通过，包含 `-Ofast`。
