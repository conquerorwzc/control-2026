# 底盘三轴速度闭环

> 2026-10-14：已移除串口调参结构依赖。以下初始参数和历史验证记录不代表当前参数；以 robot_config.h 为准。本轮未编译或运行宿主测试。

三个控制器分别为 `vx_hold_pid`、`vy_hold_pid`、`wz_hold_pid`，属于整车速度外环。名字中的 hold 表示速度跟踪，不限制为 `CHASSIS_HOLD` 模式，也不是位置保持。

## 控制链路

```text
遥控/导航目标
  → 角度环生成并叠加 wz
  → vx/vy 从云台系转换到底盘机体系（导航机体系直接通过）
  → SpeedHoldControl() 局部 target
  → 目标速度前馈 + 三轴速度 PID 修正
  → chassis_vx / chassis_vy / chassis_wz
  → 全向轮逆运动学
  → 四个电机速度 PID
  → 现有功率限制与电机输出

四轮测速 + IMU → 速度 EKF → speed_observer.fused → 三轴速度 PID 反馈
```

全部速度在底盘机体系下比较，原点为底盘几何中心：+x 朝电池、+y 向左、+wz 俯视逆时针。vx/vy 单位 m/s，wz 单位 rad/s。

```c
vx_out = vx_target + PIDCalculate(&vx_hold_pid, speed_observer.fused.vx, vx_target);
vy_out = vy_target + PIDCalculate(&vy_hold_pid, speed_observer.fused.vy, vy_target);
wz_out = wz_target + PIDCalculate(&wz_hold_pid, speed_observer.fused.wz, wz_target);
```

PID 的误差为 `target - feedback`，正增益会在实测速偏低时提高逆解输入。保留目标前馈，因此外环小增益仍能输出接近原有的电机目标。修正只作用于本周期局部量，不写回遥控/导航原始命令，避免逐周期累加。

例如 vx 目标为 1.0 m/s、融合反馈为 0.8 m/s、Kp=0.2 且尚未触发限幅时，PID 修正为 +0.04 m/s，逆解输入为 1.04 m/s。

## 配置与初值

配置位于 `UserApp/robot/sentry_omni_chassis/robot_config.h` 中的 `chassis_init_config`：

| 参数 | vx_hold_pid | vy_hold_pid | wz_hold_pid |
| --- | --- | --- | --- |
| Kp | 0.2 | 0.2 | 0.2 |
| Ki / Kd | 0 / 0 | 0 / 0 | 0 / 0 |
| DeadBand | 0.01 m/s | 0.01 m/s | 0.02 rad/s |
| MaxOut，修正限幅 | ±0.5 m/s | ±0.5 m/s | ±1.0 rad/s |
| IntegralLimit | ±0.2 m/s | ±0.2 m/s | ±0.4 rad/s |

`enable_speed_hold=1` 开启三轴外环，设为 0 恢复原有目标速度直接逆解。现值是保守调试初值，未经过实车稳定性和响应整定。当前实际仅使用 P；配置仍提供完整 PID 参数供后续调整。

MaxOut 限制的是 **PID 修正量**，不是目标前馈与修正相加后的整车最高速度。原有电机速度环与功率控制继续存在。后续启用 Ki 时，应结合电机输出/功率饱和观察积分累积；现有 PID 积分限幅不会自动获知下游功率削减的大小。

## 状态切换与反馈资格

- `CHASSIS_POWER_OFF`：清空三个速度 PID 的积分、输出与历史，本周期逆解速度目标全部置零；电机仍按原急停逻辑停用。
- 外环关闭或融合速度不可用：清空三个 PID，回到原有速度前馈，不用旧估计继续累积误差。此动作不新增电机离线急停策略。
- 首次使能和测速恢复：清空 PID 并预置当前反馈、误差和 DWT 时钟，首周期只有前馈，下一周期开始补偿，避免长间隔积分及恢复时微分冲击。
- 正常速度目标为零且底盘仍使能：外环可以输出反向修正以抑制实测速偏差；这与底盘关闭输出不同。
- 非有限目标速度：本周期目标置零，并退出外环；非有限 PID 输出也会被拒绝并清空。检查使用 IEEE-754 位模式，在 `-Ofast` 下仍有效。

`speed_observer.valid` 要求本周期估计成功、已获得初值、dt 合理、输出有限、四轮在线且反馈未超时，以及最近一次成功轮速校正距今不超过 `observer_sensor_timeout`（当前 20 ms）。正常 CAN 更新间隔内允许短时预测；纯预测持续运行不能无限延长反馈有效期。发生超长 dt 的周期不运行速度 PID，即便 EKF 成功重置。

这仍依赖现有电机在线判断和 IMU 驱动。IMU 超时由观测器原有逻辑停用相应输入，轮速正常时可继续使用轮速支持的估计；不将 INS 更新计数当作新增硬件故障检测。
