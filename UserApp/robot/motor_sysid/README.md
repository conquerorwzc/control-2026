# motor_sysid：独立机器人：髋关节扫频与 VOFA

本目标自行拥有遥控、VOFA 和已选髋电机实例，无需启动另一个机器人或从它取得句柄。RobotInit 校验配置并初始化外设接口；实机模式在 RobotInit 里直接执行一次注册，无需拨杆触发，使用队内 DMMotorInit、SetRef/Stop，并为每个实例启动**原 DMMotorTask**（同队内 leg_length_demo 的用法）。发送器不是新驱动；500 Hz 试验、关节 PD、保护、下发与记录都在 robot 层，不改 OSTask 或 Modules/BSP/Hardware。标定参数均在 robot_config.h。使用已校准的逻辑关节角，不需要另写腿长逆解。

**默认仍为空跑**：SYSID_REAL_HIPS=0，完全不注册电机，不会发送使能帧。真机分支不是“去掉一行判断就能上车”；未填标定、滤槽不足、驱动未就绪、反馈无效都不会进入出力状态。

## 拨杆

| 左拨杆 | 行为 |
|---|---|
| 下 | 软件急停/取消。仅表示停止参考激励，不是物理急停或驱动器硬件失能。 |
| 中 | 准备：右上慢速正弦往返，右中线性扫频，右下平滑平台。 |
| 上 | 使用准备时选择的模式。运行中切换右档不会直接跳到另一种激励。 |

每轮先在线左下→左中选档→左上运行。上电处于上档不启动；完成、中断、遥控离线后重新走这套流程。CH3 的状态值按 sysid_runner.h：0 等急停、1 急停、2 准备、3 起始、4 实机运行、5 完成、6 故障、7 空跑。CH4：0 无、1 慢速正弦、2 扫频、3 平台。慢速正弦不等于静摩擦起动试验或恒速三角波。

## VOFA+

默认使用本目标专用 USART1，机器人初始化时设置 **1,000,000 baud、8N1**（H7 原 USART1 是 115200，不改 Hardware）；遥控仍为 UART5，两者不能共线。VOFA+ 选择 **JustFloat**，按 CH0…CH23 录制，用户从 VOFA 导出 CSV 即可，不用运行 PC 串口脚本。每拍 24 个 float + 4 B 帧尾 = 100 B；500 Hz 合计 50 kB/s，含 8N1 约 500 kbit/s。总上限 1 Mbit/s，不是 1 MB/s。若上一帧 DMA 未结束，本拍不覆盖其缓冲、不阻塞控制，下一帧序号能看出缺拍；软件计算不等于实测链路无丢帧。

- CH0 序号（模 65536），CH1/2 板端微秒时戳高/低 16 位，CH3/4 状态/档位，CH5 标志位。
- CH6–21 按左前、左后、右前、右后，每组占四个字段：实测角、实测速度、限幅后力矩命令、反馈力矩。实机填写逻辑关节端数值；空跑或未安装的通道为占位零，无测量含义。命令列是交付驱动的最终关节侧力矩，不是 CAN 到达回执。
- CH22/23 为本轮前、后关节参考角（rad）。上电空跑先看这两条曲线和状态。
- CH5 bit0–3 是当拍收到的各路有效新帧、bit4 为力矩钳位、bit5 为已安装各路反馈及控制节拍有效、bit6 为可用遥控、bit7 为本拍真实执行许可；高位 CH5 >> 8：0 无启动闭锁、1 配置无效、2 滤槽不足、3 注册/发送器失败、4 DM 看门狗失联。空跑 bit5/7 恒为 0；接两路不补置另两路反馈位。

构建时显式选 `-DROBOT_TYPE=motor_sysid`；不改工程默认机器人。[上位机导出后的离线工具](../../../tools/hip_ident/README.md)检查字段、序号、固件时戳和有效性，原始 VOFA CSV 不改写。当前空跑文件被拒绝作为实测拟合输入是预期结果。

## 髋台架接入前核对（未做板上验证）

1. 在 robot_config.h 填实际 J8009P 的总线、TX/RX 标准 ID、反馈载荷 ID、正向符号和零位；配置已安装关节掩码、被试侧、两个激励方向、实际中心姿态、试验轨迹、每关节 PD、角度/速度/力矩/温度和起姿门槛、反馈及节拍时限。不使用 preview 数值来补标定。符号由队内驱动在收发两侧各转换一次，应用只从转换后的 total_angle 减零位；方向与试验的同/反相是两件事。
2. **本分支 H723 每路 FDCAN 目前仅一个标准滤槽，BSP 每个电机实例占一个槽。** 当前配置下，同一条总线挂两个髋电机将明确拒绝注册；四关节同采不能靠改宏绕过。若台架允许，把同一腿两个主动关节分配到两条独立且空闲的 FDCAN，掩码用 0x3（左）或 0xC（右）；实际接线由负责人确认。0xF 供具备过滤容量的四路配置，旧四关节拟合脚本只接受四路真实新反馈。不能把左右两份独立录制拼成同拍四髋数据。
3. 核对机械支撑、独立断电急停及反馈协议后才允许实机分支。注册动作本身会短暂发送硬件使能，这是原驱动行为。上电初始化直接注册，逐个置零并 Stop；拨杆不参与注册。须四路或已选两路均有正常、新鲜反馈，只需一次**左下→左中选档→左上**才进入试验。不尝试自动纠零、自动清错或掉线自动恢复。
4. 写命令前先检查 RX 长度/ID/状态、反馈帧时间、两种温度和运行范围；首次接管检查起姿误差、速度和首拍力矩。实机只对选中侧输出限幅后的 PD，旁侧已注册关节持续置零。发生非法档位、越界、超期或反馈故障，先全组写零并 Stop，再处理遥测。原驱动离线回调会重发硬件使能并阻塞 100 ms；本目标是这些实例唯一的 daemon 服务方，在计数将耗尽时先锁停并暂停该服务，须排障重启。软件 Stop 不会断电，不保证正在发送的旧帧撤回，也不保证遥控/总线失联时立即停机；必须实测反馈方向、失联响应、收发时序与硬件急停。当前未验证 UART5 配置与具体接收机匹配，不能仅凭 online 标志当作有效遥控。
5. 当前实现范围是髋关节慢速正弦、扫频和平滑平台；恒速摩擦、弹簧专用流程及轮电机仅离地空载试验不在本轮实机接入范围。没有烧录、使能或宣称实测结果。
