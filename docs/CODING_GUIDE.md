# 代码编写规范（给 Codex）

适用于两个仓库：
- 仓库 A `wheelleg`：Python，强化学习训练和工具；
- 仓库 B `control-2026`：C，STM32 固件。

请把本文复制到两个仓库的 `docs/CODING_GUIDE.md`，并在每次布置任务的提示词里写上"先读 docs/CODING_GUIDE.md"。

**优先级：** 任务描述 > 本规范 > 仓库自带的 AGENTS.md。仓库 B 的 AGENTS.md 里关于命名、分层、通信和提交格式的规定是团队的硬约定，照旧遵守（§3.1）；其余的写法和取舍以本规范为准。

---

## 1. 核心原则

### 1.1 写能解决问题的最少的代码
- 只实现任务要求的东西。不要为"以后可能需要"预留参数、开关、接口或扩展点。真的需要时再加，那时候也更清楚该怎么设计。
- 先写对，再写简单。代码的长度不是工作量的证明，删掉的代码越多，评审越容易通过。
- 三行能写清楚的逻辑，不要拆成一个类加三个方法。

### 1.2 直接调用，不要层层转手
- 能直接调用函数，就不要包一层 Manager、Helper、Wrapper、Adapter、Factory、Registry。
- **只有当现在就有两个以上真实的使用者时，才抽象。** 只有一个实现的抽象基类、只有一个调用点的"通用工具函数"，都不要写。
- 不要在已有的库或框架外面再包一层自己的抽象，比如 Isaac Lab、rsl_rl、队内的 Bsp 和 Modules。直接用它们原本的写法。
- 一个函数只做一件事，但也不要为了"短"把连续的逻辑切成一串只被调用一次的小函数。读代码的人要跳来跳去，反而更难懂。

### 1.3 错误处理放在边界，内部信任数据
这是最容易做过头的地方，规则如下：

**只在这些"边界"检查输入：**
- 从外部读进来的数据：yaml 配置、CSV、命令行参数、CAN 帧、串口数据；
- 神经网络的输出（可能出现 NaN 或越界）；
- 数值上会出问题的位置：五连杆奇异（`det J ≈ 0`）、除以测量值、开方的参数可能为负；
- 会让机器人动起来的输出：电机力矩，**只在安全层一个地方**限幅和检查。

**边界检查过一次之后，内部代码就信任这些数据。** 不要在每一层都重新检查一遍。

**禁止的写法：**
- 吞掉异常：`try: ... except: pass`、`except Exception: return None`，或者 C 里出错后默默返回 0 继续运行；
- 必需的数据缺失时，悄悄用默认值顶上：`cfg.get("kp", 20.0)`、`getattr(obj, "x", 0)`、`if x is None: x = 0`。缺了就应该报错；
- 用 `hasattr`、`isinstance` 去猜输入是什么类型，然后走不同的分支。输入的类型应该是确定的；
- 没有原因的重试循环，例如"失败了再试 3 次"；
- 每个函数开头都写一串 `assert x is not None`；
- 在 C 的每个函数里各自限幅（`if (t > 40) t = 40;`），导致限幅散落在十几个地方；
- 为了兼容根本不会用到的版本写的兼容代码。

**该报错就大声报错：**
- Python：`raise ValueError(f"robot.yaml 缺少字段 {key}")`，信息里写清楚是哪个文件、哪个字段、期望什么；
- 固件：异常进入安全状态机（SAFE_STOP 或 FAULT），并记录错误码，不要就地"修好"后继续运行。

### 1.4 不要猜
- **物理参数、硬件行为、第三方 API，不确定就不要编。** 写进任务汇报的"待确认"里，代码里用配置项代替，并在注释里标 `TODO(待确认): ...`。
- 不要凭印象写 Isaac Lab、X-CUBE-AI、HAL 的函数名和参数。先在仓库里或已安装的包里找到它的定义；找不到就列为待确认。

### 1.5 改动范围只限于任务
- 不要顺手重构、重命名、重新格式化和任务无关的代码。看到了问题就写进汇报，不要自己改。
- 不要改已有的公共接口（函数签名、结构体字段、配置字段名），除非任务明确要求。必须改时，在汇报里列出所有受影响的调用点。
- 一个提交只做一件事，diff 要让人能在 10 分钟内看完。

### 1.6 注释和命名
- **注释写"为什么"，不写"做了什么"。** `# 乘以 0.25 是因为训练时角速度观测缩放为 0.25（指南 §5.2）` 是好注释；`# 角速度乘以 0.25` 是废话。
- **物理量都要写清单位和坐标系**，写在变量名里或者第一次出现的注释里：`ang_vel_b`（机体系）、`wheel_vel_rad_s`、`spring_len_m`、`tau_nm`。
- 来自开源仓库的代码，在注释里写明来源：`# 改自 SCUT wheelbipe25_v3/env.py:5554-5574`。
- 中文注释可以用，标识符一律用英文。
- 不要写大段的文档字符串去复述函数名已经说明的内容。只在输入输出的形状、单位、前提条件不明显时写。

## 2. 仓库 A（Python，强化学习）

### 2.1 基本约定
- Python 3.11；格式化和检查用 `ruff format` 和 `ruff check`，每行最多 120 字符。
- 公开函数要写类型标注；张量参数在注释里写明形状和单位，例如 `# (N, 35) float32`。
- 只用 Isaac Lab 2.3.2、rsl_rl 以及 SCUT 仓库已经依赖的库。**不要引入新依赖**，确实需要时先在汇报里说明理由。

### 2.2 配置
- `config/robot.yaml` 和 `config/policies/*/policy_meta.yaml` 是**唯一的**参数来源。代码里不允许出现物理参数的数字字面量，比如杆长、质量、PD 增益、缩放系数、限幅。
- 配置**只在加载时校验一次**：必填字段齐不齐、单位和取值范围对不对。校验失败就报错，指明文件和字段。加载后得到一个 `dataclass(frozen=True)`，显式地作为参数传下去。
- 不用全局可变状态；除了文档里写明的少数几个，不用环境变量控制行为。

### 2.3 Isaac Lab 和训练代码
- **照 Isaac Lab 的写法来：** 用它的配置类、事件（event）、奖励项（reward term）、观测项（observation term）的机制，不要自己再发明一套。
- 从 SCUT 复制代码时，复制到 `isaac/wheelleg_tasks/` 下修改，并注明来源。不要修改 `third_party/`。
- **全部向量化：** 4096 个环境，不允许按环境写 Python 循环。需要按环境区别处理时，用掩码（mask）。
- **一项奖励一个函数**，函数名就是日志里显示的名字，返回形状为 `(N,)` 的张量。不要把多项奖励合并在一个函数里，否则日志里看不出是哪一项在起作用。
- **观测的拼接顺序只在一个地方定义**（obs_v2 布局），导出脚本、MuJoCo、固件代码生成都从这一处读取。

### 2.4 错误和日志
- 不写裸 `except`；捕获异常只在"能处理并且确实要处理"的地方，例如读取一个可以缺失的可选文件。
- 训练过程的指标走 rsl_rl 的日志（TensorBoard），不要到处 `print`。
- 运行脚本时，只在开始时打印一次关键配置（任务名、环境数、物理频率、策略频率、git commit）。

### 2.5 脚本
- 命令行参数尽量少，默认值来自配置文件。一个脚本做一件事：训练、评测、导出、辨识各自一个脚本。
- 输出的文件路径统一放在 `runs/<运行名>/` 下，不要写死绝对路径。
  - 队内 `tuning/analysis` 里的脚本写死了 `C:/Users/Dai/Desktop/...` 这样的路径，不要照抄这种写法。

### 2.6 测试
- 用 pytest，测试的是**真实的数值行为**：五连杆和 CAD 数据对比、雅可比和有限差分对比、观测布局逐维检查、导出前后数值一致、辨识脚本能从仿真造出的数据里把已知参数辨识回来。
- **不写**只断言"某个 mock 被调用了"的测试，也不要 mock 被测对象本身。
- 需要 GPU 或 Isaac 的测试单独标记（`@pytest.mark.isaac`），纯 CPU 的测试要能在本机 Windows 上运行。

### 2.7 例子
**不要这样写：**
```python
class RewardManagerFactory:
    def create(self, cfg=None):
        cfg = cfg or {}
        try:
            sigma = cfg.get("sigma", 0.25)
        except Exception:
            sigma = 0.25
        return RewardManager(TrackingReward(sigma))
```
**这样写：**
```python
def track_lin_vel(env, sigma: float) -> torch.Tensor:  # (N,)
    """机体前向速度跟踪，exp(-e²/σ)。改自 SCUT V14/env_cfg.py:869-914。"""
    err = env.command[:, 0] - env.base_lin_vel_b[:, 0]
    return torch.exp(-err**2 / sigma)
```
`sigma` 由配置类直接传入，缺了就让 Isaac Lab 报错。

## 3. 仓库 B（C，STM32 固件）

### 3.1 团队的硬约定（照旧遵守）
- **分层：** Hardware → Bsp → Modules → UserApp，下层不能引用上层。
- **实例化模式：** `XXX_Init_Config_s config = {...}; XXXInstance *inst = XXXInit(&config);`
- **模块间通信必须走 `message_center`**，应用之间不能互相 include。
- **命名：** 函数和结构体用 CamelCase，变量和成员用 lower_case，常量用 `kXxx`，配置结构体以 `_Init_Config_s` 结尾，头文件用 `#pragma once`，CAN 结构体用 `#pragma pack(1)` … `#pragma pack()`。
- **提交信息：** `<type>: <说明>`，例如 `feat: 增加 DM 电机失能接口`。PR 描述分"修改内容 / 影响范围 / 验证情况"三段。
- **分支：** 从 master 拉 `feature/...`，不直接推 master，不强推。

### 3.2 格式
- **新文件**按仓库的 `.clang-format`（Microsoft 风格）格式化。
- **已有文件不要整体重新格式化**，只让你改的那几行和周围代码风格一致。现有文件里有 2 空格缩进的，也有别的写法，保持原样。
- 编译要求 `-Wall -Wextra` 下**不新增警告**。PR 里贴上编译输出。

### 3.3 嵌入式规则
- **只用单精度：** H7 目标的编译选项是 `-mfpu=fpv5-sp-d16`，只有单精度浮点有硬件支持，`double` 会走软件模拟，非常慢。所以浮点常量一律带 `f` 后缀（`0.5f`），数学函数用 `sinf`、`cosf`、`sqrtf`、`atan2f`、`fabsf`，不要用不带 f 的版本。
- **内存：** 只在 `XXXInit()` 阶段分配内存，控制循环里不分配。数组大小用宏或常量明确写出。CubeAI 的激活缓冲区静态分配。
- **中断和回调要短：** 只读数据、置标志、拷贝到缓冲区。中断和回调里**不能**出现 `osDelay`、阻塞等待、`printf` 和大量计算。队内 DM 驱动的离线回调里有 `osDelay(100)`，这正是要修掉的反例。
- **控制循环里的时间要确定：** 500 Hz 控制任务里不能有不确定耗时的操作，比如打印、等待或者动态分配。用 DWT 测量每个周期的耗时，超时就计数并上报。
- `volatile` 只用于中断和任务之间共享的变量。多字节的共享数据用双缓冲，或者在临界区内拷贝。
- **单位统一用国际单位制**（rad、rad/s、m、N·m、N）。电机原始数据（定点数、rpm、电流值）和国际单位之间的换算**只在驱动层做一次**，上层只看到国际单位。
- **生成的文件**（`generated/` 下的 `gen_config.h`、网络 C 代码、`golden.h`）不能手改，要改就改仓库 A 的生成脚本，然后重新生成。

### 3.4 安全相关代码：这里的保护是需要的，但只放在一个地方
固件里**真正需要**的保护，集中写在应用层的一个安全仲裁函数里（例如 `WheelLegSafetyArbitrate()`）。所有电机输出都必须经过它，其他地方不再各自限幅。它负责：
- 力矩和转速限幅（数值来自 `gen_config.h`）；
- 策略输出的 NaN 和越界检查；
- 遥控离线、IMU 异常、关节越限、五连杆奇异、电机错误码、母线欠压时，切换到 SAFE_STOP 或 FAULT；
- 上电默认不输出力矩，必须经过明确的使能操作（遥控拨杆）。

这里的检查是**按物理风险设计的**，不是"防御性编程"。除此之外的代码不要再加零散的保护。

### 3.5 不要加的抽象
- 不要在现有的 Bsp 和 Modules 上面再包一层"统一硬件抽象层"。
- 不要为了"可配置"把简单的 `if` 写成函数指针表或者状态机框架。状态机直接用 `switch` 写。
- 不要写一个功能单一的模块却配一整套 Init、Register、Get、Set、Update、Destroy 接口。用到哪些写哪些。

### 3.6 例子
**不要这样写：**
```c
float LimitTorque(float t) { if (t > 40.0) t = 40.0; if (t < -40.0) t = -40.0; return t; }  // 用了 double 字面量，到处调用
void LegControl(...) {
    if (leg == NULL) return;          // 内部函数，leg 不可能为 NULL
    tau = LimitTorque(tau);           // 第 1 处限幅
    ...
}
void SendMotor(...) {
    tau = LimitTorque(tau);           // 第 2 处限幅
    osDelay(1);                       // 在控制循环里阻塞
}
```
**这样写：**
```c
// 控制任务每 2 ms 调用一次；所有限幅只在 WheelLegSafetyArbitrate() 里做
static void WheelLegControlStep(void)
{
    WheelLegReadState(&state_);                    // 驱动层已经换算成国际单位
    if (step_count_ % kPolicyDecimation == 0)
        WheelLegRunPolicy(&state_, &action_);      // 100 Hz
    WheelLegComputePd(&state_, &action_, &cmd_);   // 500 Hz，得到每个关节的 tau_nm
    WheelLegSafetyArbitrate(&state_, &cmd_);       // 唯一的限幅和保护入口
    WheelLegSendMotors(&cmd_);
    step_count_++;
}
```

## 4. 两个仓库共同的规则

### 4.1 接口变化
仓库 A 和仓库 B 之间只通过**固件包**（`gen_config.h`、网络代码、`golden.h`、`manifest.yaml`）和**遥测协议**（`docs/telemetry_protocol.md`）交换。
- **一次任务只改一个仓库。** 接口要变时，先在仓库 A 改协议文档和生成脚本，然后单独开一个仓库 B 的任务去跟进。
- 观测或动作的定义一旦改动，`obs_version` 必须加一，`manifest.yaml` 里也要带上，固件启动时检查版本是否一致。

### 4.2 测试和验证
- **仓库 A：** `pytest` 全部通过；涉及训练的改动，要附上冒烟训练（512 个环境、200 轮）的曲线截图。
- **仓库 B：** H7 目标能编译通过，没有新增警告，附上 `.map` 里的 Flash/RAM 占用。**本次修改没有在硬件上测试的话，要明确写出来**，不要写成"已验证"。

### 4.3 完成任务时的汇报格式
```
## 修改内容
- 改了哪些文件，每个文件一句话说明为什么改
## 怎么运行 / 怎么验证
- 命令和预期结果
## 测试结果
- 实际输出（复制原文，不要概括）
## 影响范围
- 会影响哪些已有功能、哪些机器人目标
## 待确认
- 不确定的物理参数、硬件行为、API；需要人决定的地方
## 发现但没有改的问题
- 任务范围以外看到的问题
```

### 4.4 交付前自查（每一条都要过）
- [ ] 只做了任务要求的事，没有顺手重构，也没有重新格式化无关代码。
- [ ] 没有新增的 Manager、Factory、只有一个实现的基类，也没有只用一次的工具函数。
- [ ] 没有吞掉的异常，没有用默认值掩盖缺失的配置，没有零散的保护代码。
- [ ] 所有物理参数都来自配置，代码里没有物理量的魔法数字。
- [ ] 单位和坐标系都写清楚了。
- [ ] C 代码里没有 double 字面量或不带 f 的数学函数；中断和回调里没有阻塞。
- [ ] 测试测的是真实数值，并且都通过了；仓库 B 编译通过、没有新增警告。
- [ ] 不确定的内容都写进了"待确认"，没有自己猜一个值。
