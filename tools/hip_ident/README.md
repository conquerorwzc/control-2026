# 髋关节 WP-ID（离线力矩回放初版）

1127 电池版实机使用 [无簧台架操作单](BENCH_1127.md)。顺序为先无簧，结束并留好基线，再装簧复测。该流程使用单位比例的 CAN 反馈力矩。下面的旧四髋配置仍使用下发力矩回放。

本工具不控制硬件。实验不装气弹簧。需要真实固定机身闭链 MJCF，保留完整腿质量、轮子惯量及被动关节；禁用气弹簧，不得用示例机器人代替。MJCF 不含 actuator，使用 qfrc_applied 施加关节侧力矩。初始 keyframe 必须提供被动关节的正确闭链装配分支。

依赖：numpy、mujoco（新增离线依赖，因回放必须调用物理引擎；不影响固件构建）。

运行：python tools/hip_ident/fit_real2sim.py tools/hip_ident/config.json
所有路径相对执行目录。复制 config.template.json 为 config.json，补齐 null 后运行。

CSV：time_s，以及每个逻辑关节的 <joint>_q_rad、<joint>_qd_rad_s、<joint>_tau_cmd_nm。必须为无丢帧 500 Hz 数据。角度已标零和统一方向，力矩是保护限幅后、关节侧最终命令，不能用反馈力矩替代。开始前应稳定保持并记录一段稳态历史。温度、电流、帧号等额外列允许保留；录制侧另行检查重复反馈、饱和和故障。

## 当前默认采集

当前默认一次采完右腿无簧的 117 项。双上后自动完成基线 25 项（含双向静态网格），随后完成六工作点动态测试 92 项，导出一份 VOFA CSV。工作点 6 留作验证。遥控步骤和完成标志见[操作单](BENCH_1127.md)。

单腿 CH7/CH16 的基线分别给出前、后工作点，CH3 记录实际激励组合和阶段。四髋布局另存本次 `robot.hip_workpoint_rad`，便于重建右腿参考。随录制保存 Kp/Kd、幅值、扫频限矩、装簧状态和温度。用扫频及阶跃估计等效惯量和延迟；用静止缓升估计起动摩擦，用多速度正反匀速段拟合运动摩擦和黏性阻尼。留出一个完整姿态或一组独立轨迹验证。

## VOFA+ 导出 CSV：现行 25 通道

用 VOFA+ 的 JustFloat 录制 `CH0` 到 `CH24`。每帧 104 字节，500 Hz、8N1 占用 520 kbit/s，默认串口为 1 Mbaud。保留原始录制、编译所用的 robot_config.h 和覆盖的编译宏，用于关联本轮的工作点和增益。仅在转换时选择实机运行段，行号从 1 开始且不计表头。

```powershell
# 单腿双髋，保留全部反馈/命令时间与原始反馈字段
python tools/hip_ident/vofa_csv.py hip_vofa.csv --format sysid-hip --start-row 201 --end-row 5200 --output hip.csv

# C620 双轮或单轮离地采集
python tools/hip_ident/vofa_csv.py wheel_vofa.csv --format sysid-wheel --start-row 201 --end-row 5200 --output wheel.csv

# 确保实际四路执行，并按旧四髋拟合器要求检查 500 Hz 时间步
python tools/hip_ident/vofa_csv.py four_hips_vofa.csv --format sysid-hip --required-mask 0xf --start-row 201 --end-row 5200 --output train.csv
```

默认按通道名找列。自定义表头可用 `--channel-map` 传入按通道号排序的 25 个实际列名。转换保留时间间隔实际值、诊断位和固件字段。双髋单腿和轮工况在反馈仍有效时允许某拍没有新反馈，且报告时间步偏差，供后续按实际时间戳对齐。控制拍序号中断、倒退、故障、无效反馈、执行未开放和段内工况切换会拒绝导出；同一工况内的阶段变化可以导出。四髋回放须通过 `--required-mask 0xf` 施加旧拟合器的严格时间步及反馈检查。

共用通道如下。

| 通道 | 内容 |
| --- | --- |
| CH0 | 控制拍序号，模 65536。串口忙时也前进。 |
| CH1–2 | 本拍板端微秒时戳高、低 16 位，合计模 2³²。转换器展开回绕并生成从 0 起算的 `time_s`。 |
| CH3 | bit 0–3 状态，4–7 实验编号，8–9 髋关节激励组合，10–12 阶段，13 负向位，14 单腿侧（0 左、1 右），15–16 布局（0 四髋、1 单腿、2 轮、3 配置），17 及以上为版本 3。 |
| CH4 | 低八位为模式，高位为工作点 ID（旧录制为 0）。模式对应 `robot.h` 中的 `SysIdMode`。 |
| CH5 | bit 0–5 本拍有效新反馈；6 遥控在线；7 实机执行；8 发生限幅；9 故障标志（旧帧用 9–11 记录故障码）；12–17 反馈有效；18–23 实际应用的通道。三个 6 位掩码顺序均为左前、左后、右前、右后、左轮、右轮。 |

单腿和轮布局 CH6 为命令发布时间减 CH1–2 的本拍时刻，单位 µs。CH7–15 是前髋或左轮，CH16–24 是后髋或右轮，两组顺序固定如下。

| 布局 | 组内字段顺序 |
| --- | --- |
| 单腿 | 角度参考 rad、实测角 rad、实测角速度 rad/s、限幅前扭矩 N·m、下发扭矩 N·m、换算后反馈扭矩 N·m、MIT 原始 12 位扭矩反馈、温度 °C、反馈时刻相对本拍的偏移 µs |
| 轮 | 速度参考 rad/s、直接电流参考 A、轮侧速度 rad/s、限幅前电流 A、下发电流 A、C620 原始电流反馈计数（统一逻辑方向）、温度 °C、反馈时刻相对本拍的偏移 µs、直接电流模式标志 |

在转换结果中，用 `time_s + offset_us / 1_000_000` 得到对应的相对时间。偏移 `-16777216` 表示未观察或超出可编码范围，未启用的通道以掩码判定。命令时戳是控制层发布到驱动的时刻，反馈时戳从驱动接收回调更新的周期计数换算。两者可用于约束延迟，CAN 上实际发送和电机内部采样另需量测。参考速度只适用于轮速控制模式，直接电流参考只适用于模式标志为 1 的行，其中含零电流滑行。髋 PD 只生成位置参考，无独立速度参考。髋驱动未提供电流反馈。MIT 扭矩的协议及传动换算值和台架负载校正是不同数据，后者未实时应用。母线电压、外部扭矩校正及标定报告可另记并按运行关联。

四髋布局 CH6–21 保留四路同拍角度、速度、下发扭矩、反馈扭矩，CH22–23 固定为左前、左后参考，右侧可用已保存的工作点、方向和激励配置还原。CH24 依 `seq % 4` 轮换四髋温度，转换时追加 `hip_temperature_joint`。这组布局仅保留统一控制拍时间，以及反馈有效和更新位。需要每髋反馈时刻、限幅前扭矩、原始反馈和每拍温度时，用单腿布局录制。

以下配置页用于旧版 25 通道录制的解码。读取含配置页的旧录制时可使用 --metadata-output 导出 JSON，结果包含选段前收到的匹配页及原始 CSV 行号。

| 页号 | 内容 |
| --- | --- |
| 0 | 工作点 ID 高、低 16 位，方向，所选激励参数，实机开关，配置有效标志，髋安装掩码和轮安装掩码 |
| 1–4 | 对应髋的工作点角度、安装标志、实际 Kp/Kd、扭矩上限、零位、电机方向和减速比 |
| 5–6 | 对应轮的安装标志、实际速度环增益、电流上限、电机方向和减速比 |
| 7 | 扫频起止频率、扫频时长和淡入淡出时长、阶跃基线/保持/恢复时长、稳速时长、滑行时长、保持扭矩均值窗口、起动确认窗口、三角周期数、髋缓升增量上限与起动速度阈值、轮缓升电流上限与起转速度阈值、三角幅值 |

## 旧 VOFA+ 24 通道 CSV

`vofa_csv.py` 只读已导出的 CSV，不连接串口、不操作 VOFA+，只依赖 Python 3 标准库。在仓库根目录运行：

```powershell
# 仅检查整份录制；问题按类型报告次数和首个位置
python tools/hip_ident/vofa_csv.py vofa_train.csv

# 只转换指定区间；行号从 1 开始，不含表头，两端都包含
python tools/hip_ident/vofa_csv.py vofa_train.csv --start-row 201 --end-row 5200 --output train.csv
```

用另一份独立实验录制得到 `validation.csv`，将两份输出分别填入配置的 `train_csv` 和 `validation_csv`。选段应保留激励前的稳态历史；脚本不自动选段。导出至少需要两行，输出目录须已存在，不覆盖既有文件。可指定同样的行范围但省略 `--output` 做预检。检查失败退出非零；文件内可定位的问题即使在选段外也会报告，但不阻止干净选段的导出。只有区间内的行和内部相邻行之间的变化计入选段判定。

输入为带表头的 UTF-8 逗号 CSV（允许 BOM）。默认按名称查找 `CH0` 到 `CH23`，与文件内列的摆放顺序无关；多余列不参与校验。若导出表头被改名，用 `--channel-map channels.json` 明确提供 24 个实际表头名，数组位置就是通道号，每个名字只能对应唯一一列。下面示例适用于表头已改为协议字段名的文件，也展示了通道顺序：

```json
[
  "seq", "t_hi", "t_lo", "state", "mode", "flags",
  "left_front_q_rad", "left_front_qd_rad_s", "left_front_tau_cmd_nm", "left_front_tau_fb_nm",
  "left_rear_q_rad", "left_rear_qd_rad_s", "left_rear_tau_cmd_nm", "left_rear_tau_fb_nm",
  "right_front_q_rad", "right_front_qd_rad_s", "right_front_tau_cmd_nm", "right_front_tau_fb_nm",
  "right_rear_q_rad", "right_rear_qd_rad_s", "right_rear_tau_cmd_nm", "right_rear_tau_fb_nm",
  "q_ref0_rad", "q_ref1_rad"
]
```

- **时间与连续性**：只用固件 `(t_hi << 16) | t_lo`（32 位微秒计数），不使用 VOFA+ 的 `Time`、主机时间或行号推算。按原文件顺序检查 `seq` 模 65536 每拍加 1、时间每拍 2000 µs（按现有拟合器的 ±1 µs 浮点检查），允许正常回绕；重复、跳号、倒退/疑似重启、间隔异常及段内 `state`/`mode` 变化都会拒绝。不能从 CSV 判定首条记录之前、末条之后是否有丢帧，也不能对回绕与碰巧同时满足序号和时间连续的复位作区分。
- **真实执行**：每行都要求 `flags` bit 7 为 1，bit 5 驱动就绪、bit 6 遥控在线；空跑或执行中断的行不能进入实测选段。bit 4 为 1 时报告命令限幅，保留限幅后的 `tau_cmd_nm`；bits 8–9 不用于判断。bit 7 表示固件允许真实执行，并不单独证明电机实际出力。
- **反馈新鲜度**：每行必须四髋都由 `flags` bits 0–3 标为本拍新反馈，依次对应 `left_front`、`left_rear`、`right_front`、`right_rear`。不按数值是否重复猜测新鲜度。某髋没更新就拒绝整个选段，不删坏帧后拼接，不前向填充或插值；若固件反馈频率不足以形成连续四髋新鲜区间，需重新采集，而不是放宽检查。新鲜位也不代表四个反馈具有相同的精确采样时刻。
- **输出**：每条入选记录原样保留信号数值及协议字段，另加从首帧归零的 `time_s`（由实际固件时间差展开）；不重采样、不补帧、不用 `tau_fb_nm` 替代命令。协议列缺失、映射含歧义、选段内有坏行或 CSV 结构无法解析时不生成拟合输入。

## 拟合与验收

参数顺序：4 armature (kg m²)、4 frictionloss (N m)、4 damping (N m s/rad)、4 torque scale、1 command delay (s)。均为关节侧参数。bounds 必须是17对实测有依据的上下界，禁止猜测。delay 为2 ms采样分辨率的等效命令延迟，非传感器延迟；辨识前先对齐反馈采样时间。已知反馈延迟不能让脚本错误地吸收到动力学中。

算法：可复现的有界随机搜索，包含边界中点基线；不保证全局最优或参数唯一。独立验证集不参与搜索。输出 fit.json、train_replay.csv、validation_replay.csv，可直接绘制实测与仿真叠加图。误差为每关节RMSE；此初版不自动判断相位是否源于延迟，不自动写回robot.yaml。差的参数边界可能导致仿真发散，工具会停止报告，不能静默吞掉模型问题。

重要限制：这是最终力矩命令回放，不是位置指令闭环回放；不能据此宣称已验证固件PD或内部电机控制器。需要额外使用留出的位置指令及实际控制律做闭环验收。真实数据缺失、模型缺失时不产出实车参数。尚待真实MJCF与实验数据端到端验收。
